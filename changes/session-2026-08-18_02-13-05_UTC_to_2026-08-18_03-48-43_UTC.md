## Risks / Follow-ups

- `ios`, `macos`, and `linux` are declared in the manifest but unimplemented ΓÇö they exist so the menu is honest, not because they work.
- `after-clone-command` is documented as not read by the TUI, so `npm install --prefix scripts/electron` must be run by hand or Windows builds cannot work at all.
- The Windows path splits staging across two roots: `windows-web` and `windows-installer` live under the scaffold repo (per `scripts/electron/package.json`), while every other platform stages under `<project>/.build-temp`. Moving one of those two paths requires moving the other.
- `build/<folder>` uses the manifest key verbatim, so `windows` publishes to `build/window` ΓÇö a typo-looking path that is now load-bearing.
- Build-time deletion of `<project>/dist` and `<project>/release` is the one place this repo removes something it did not create; a project that keeps real content at either path would lose it.
- No build was smoke-tested in this session ΓÇö doing so needs a real Expo project. The graph report also flags `build-platform.mjs` as low-cohesion (0.07) with many isolated nodes, though that is a structural observation, not a defect.
